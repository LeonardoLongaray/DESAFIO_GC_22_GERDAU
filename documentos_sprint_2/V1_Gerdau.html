    Como funciona
    
  
    Guia curto para quem vai usar ou avaliar o protótipo.
    
  
    O problema
    
  
    O mesmo serviço aparece no SAP escrito de várias formas (“manutenção de motor”, “manut. motor elétrico”). Cada grafia vira um código diferente e a base fica duplicada. Este sistema impede que isso volte a acontecer.
    
  
    Passo a passo do comprador
    
  
    1. Digita o serviço. A tela corrige erros e sugere as opções oficiais.
    2. Clica na opção oficial e escolhe o horário (hora normal, hora extra etc.).
    3. O sistema junta ação, objeto, horário e NBS em um código único para o SAP.
    4. Se o comprador digitar um texto livre sem escolher uma opção, o sistema compara o texto com a base e decide pela tabela abaixo.
    
  
    Regra de decisão
    
  
    SimilaridadeAção do sistemaO que acontece
    
  
    Acima de 0,90Bloqueio e sugestão diretaO comprador reutiliza o código existente de forma automática.
    
  
    0,72 a 0,89Alerta de advertênciaVai para a fila de aprovação e revisão manual.
    
  
    Abaixo de 0,72Liberação do cadastroO novo item é cadastrado na base com código provisório.
    
  
    Termos
    
  
    • NBS: catálogo oficial de serviços usado como base limpa.
    • Busca fuzzy: encontra textos parecidos mesmo com erros de escrita.
    • pg_trgm: extensão do PostgreSQL que compara palavras por trechos de 3 letras (trigramas).
    • Smart Key Builder: monta o código final. Exemplo: MANUT + _MOTORE + _HES + 3313000.
    
  
    Limitações do protótipo
    
  
    • Usa uma base simulada de 15 serviços, não o catálogo NBS completo.
    • A API e o banco são simulados no navegador. A integração com Spring Boot e PostgreSQL ainda será feita.
    • A correção de erros usa só as palavras da base atual.
    • O histórico fica salvo apenas neste navegador.
